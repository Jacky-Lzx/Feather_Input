# macOS 真实客户端验收应用

该应用是普通 AppKit 文本客户端，不链接 Feather Swift bridge、Rust 核心或 librime。按键
只有经过 macOS Text Input Services 和已安装的 InputMethodKit bundle 后，才会在文本框
中形成预编辑或上屏文本。

运行：

```sh
scripts/run-macos-client-acceptance.sh
```

运行脚本只在检测到 `FeatherInputRustDev.app` 已安装且 Hans 输入模式已启用时启动应用，
不会自动切换当前输入源。应用中的检查框只是人工记录，不会把观察结果伪装成自动测试。

建议先输入 `shijie` 验收紧凑候选，再清空文本并输入 `shi` 验收全词候选：

1. 用上下键改变紧凑候选高亮，用左键或 Page Up / Page Down 翻页；
2. 按右方向键展开全词候选，确认四个方向键可以跨行、跨列移动；
3. 确认只有当前列显示数字，数字键选择当前列对应候选；
4. 按 Tab，确认客户端按键状态显示 `Tab`，且输入法没有主动关闭全词候选；
5. 重新输入 `shi` 并持续向右移动，确认越过第 40 项后继续出现候选；
6. 按 Esc，确认预编辑和候选窗同时消失，且没有文字上屏。
7. 单击右 Control 切换到英文，确认状态提示出现且字母直接进入文本框；再次单击切回中文；
8. 使用 `Control + Shift + Space` 重复切换，并确认组合中的拼音会被取消而不是上屏。
9. 从输入法菜单选择“小鹤双拼”，输入 `uijp`，确认候选中出现“世界”；
10. 在英文模式切换全拼/小鹤双拼，确认仍保持英文，随后切回中文与全拼。
11. 打开“设置…”，修改默认输入方案与模式记忆策略，关闭后再次打开确认选择已保存；
12. 在存在预编辑时打开设置，确认组合被取消且没有文字意外上屏。
13. 保持“焦点状态提示持续到开始输入”关闭并将时间设为 3.0 秒，切换输入框，确认插入点旁显示当前中英文状态并自动消失；
14. 打开“持续到开始输入”，重新切换输入框，确认提示保持显示，并在开始按键或失焦后消失。

随后继续检查空格、回车、鼠标点击、修饰键快捷键、密码框和明暗外观。每一项都需要
人工观察后勾选；状态文字只证明客户端收到了对应按键，不能自动证明候选窗行为正确。

该应用能够稳定复现普通 AppKit 文本框、密码框和快捷键放行行为，但仍不能代替
TextEdit、终端、浏览器和代码编辑器的最终验收。
