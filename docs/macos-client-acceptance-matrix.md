# macOS 真实客户端验收矩阵

本矩阵用于记录 `Feather Rust Dev` 在真实文本客户端中的行为。它不会覆盖或替换 `main`
版本；开发输入法使用独立 Bundle ID、安装路径和用户数据目录。开始前先运行：

```sh
scripts/install-macos-input-method.sh
scripts/capture-macos-client-acceptance-baseline.sh
```

人工验收只使用测试文本，例如 `shijie`、`世界`、`uijp` 和 `githu`，不得在密码、Token
或其他敏感字段中输入真实数据。

## 每个普通文本客户端的必测行为

1. 输入 `shijie`，确认预编辑存在、候选包含“世界”，窗口位于插入光标附近。
2. 检查上下或左右移动、翻页、全词候选、数字键、空格、回车、鼠标和 Esc。
3. 切换竖排／横排以及 14／17／24 号字，确认键盘语义和窗口测量一致。
4. 使用右 Control、`Control + Shift + Space` 和 Caps Lock 切换中英文。
5. 输入 `shijie@`，确认原样提交且没有默认选择当前候选。
6. 切换小鹤双拼并输入 `uijp`，确认候选包含“世界”。
7. 输入 `githu`，确认混合英文候选阈值生效。
8. 切换输入框、应用和输入法，确认组合、候选窗、焦点提示及常驻提示正确清理。
9. 确认客户端自己的 Command、Control、Option、Tab 和功能键没有被错误吞掉。
10. 重复激活、输入和停用至少 30 次，确认没有崩溃、残留浮层或持续增长的窗口。

## 安全输入验收

- 聚焦密码框时不显示预编辑、候选窗、焦点提示或左下角常驻提示。
- 按键必须直接交还客户端，输入法不得记录、缓存或发送文本。
- 从密码框返回普通文本框后，输入法能够恢复且没有遗留组合。

## 多显示器验收

- 候选窗跟随当前插入光标所在显示器，而不是固定在主显示器角落。
- 光标靠近四条屏幕边缘时，候选窗仍位于可见区域。
- 主屏幕变化、显示器断开和 Space 切换后，常驻提示移动到新的主屏幕左下角。
- 全屏应用中候选窗和提示窗层级正确，不抢占键盘焦点。

## 缺陷处理

每个失败项应记录客户端版本、输入步骤、预期结果、实际结果、显示器布局和是否能够稳定
复现。修复应使用独立分支，并在提交前增加自动回归检查；无法自动化的 AppKit 行为至少
需要添加确定性的几何或生命周期测试。
