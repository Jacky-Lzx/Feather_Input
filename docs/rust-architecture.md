# Feather Input 跨平台 Rust 架构

## 目标

Feather Input 需要让操作系统适配层、输入语义、输入引擎和可选模型推理能够彼此
独立替换。当前 Swift/InputMethodKit 应用继续正常工作，新的架构则在实现分支上
接受审核。

同一套接口需要支持两种输入引擎：

1. 在功能对齐阶段使用的 librime 适配器；
2. 将来完全使用 Rust 编写的输入引擎。

平台适配层不得依赖 librime 候选索引、方案对象或全局引擎状态。

## 运行时边界

```text
macOS IMK / Windows TSF / Linux Fcitx 或 IBus
                    |
                 稳定 C ABI
                    |
             Feather 输入核心
        事件 -> 状态 -> 效果与快照
                    |
             InputEngine trait
              /             \
       librime 适配器     Rust 引擎
                    |
              可选 AI 提供者
           进程内实现或本地进程
```

按键主链路为“平台适配层 → 核心 → 引擎”，始终在同一进程内执行。模型推理是可选的
异步能力，不对组合状态或候选身份拥有最终决定权。

## 状态所有权

### 平台适配层

- 将原生按键和生命周期回调转换成核心能够理解的标准事件。
- 持有原生客户端句柄、光标几何信息、窗口层级和渲染对象。
- 执行设置 marked text、上屏文字和显示候选窗口等效果。
- 将核心使用的 UTF-8 光标位置转换成平台要求的坐标格式。

### Feather 核心

- 管理激活状态、输入模式、标准化事件分派和平台效果。
- 拒绝来自旧 revision 的候选选择。
- 提供包含不透明候选 ID 的不可变候选快照。
- 不依赖 AppKit、TSF、Fcitx、librime、HTTP 或模型运行时。

### 输入引擎

- 管理组合解析、词典、学习数据和候选生成。
- 实现原子化的命令与快照接口。
- 返回不透明的引擎候选 ID，而不是显示位置。
- 不直接向操作系统文本客户端上屏。

### AI 提供者

- 接收有长度限制、不可变并且包含截止时间的状态快照。
- 返回带请求 revision 的候选 ID 或生成候选。
- 可以由 MLX、llama.cpp、其他本地运行时实现，也可以完全不存在。
- 不得直接修改引擎状态，也不得让按键处理等待模型推理。

## 候选身份

公开候选 ID 由 `(revision, engine_id)` 组成。只有两部分都仍然存在于当前快照时，
平台返回的候选选择才会被接受。

候选文字仅用于显示，不能充当选择身份。重复候选文字是合法的，而且 AI 调整后的
显示顺序可能与引擎顺序不同。

## 引擎替换规则

`InputEngine` trait 是替换引擎的唯一接口。librime 实现可以在内部把命令转换成
Rime 按键事件和候选迭代操作。未来的 Rust 实现可以使用解析器、音节图、词典 FST、
语言模型和用户学习数据库。任何实现都不能通过 trait 泄漏这些内部表示。

初始 trait 有意保持精简。只有当至少一个与平台无关的用户行为确实需要新操作时，
才应该扩展它。引擎专属调试和管理功能应放在单独的能力接口中，而不是混入按键事件
接口。

## ABI 规则

- ABI 具有显式版本号和不透明 session handle。
- 调用方拥有 session；每个响应对象需要单独释放。
- 字符串采用 UTF-8，并且只在对应响应被释放前有效。
- 候选身份以整数 ID 加 revision 的形式跨越 ABI 边界。
- 同一 ABI 主版本内，结构只能在末尾追加字段。
- Rust、Swift、C++、Python 或操作系统对象均不得直接跨越边界。

## 迁移步骤

1. 保留当前 Swift 实现作为行为基准。
2. 为组合、翻页、模式切换、过期 AI 响应、无选区客户端和安全输入记录标准化
   行为 trace。
3. 实现 librime 版本的 `InputEngine`，将它的 trace 与当前应用进行比较。
4. 在开发开关后面让 macOS 适配层接入 C ABI。
5. macOS 行为对齐后再实现第二个平台；建议使用 Windows TSF 验证桌面跨平台边界。
6. 在相同 trait 后实现原生 Rust 引擎，并让两种引擎运行同一套 trace 测试。

移动平台适配层可以复用核心，但不能假定本地模型进程能够常驻。因此 AI 提供者必须
同时允许进程内实现和 IPC 实现。

## 当前实现状态

`feather-engine-rime` 已作为第一个真实引擎适配器接入。它负责 librime 的全局
生命周期、session、方案选择、按键映射、候选快照和全局候选选择。Rime 的 C 类型
与候选索引不会越过该 crate；核心和平台层只接触 `InputEngine`、revision 和不透明
候选 ID。
